## Executive Summary

This security audit reviewed the Vexus cryptocurrency exchange Java backend across 18 finding candidates. The platform implements spot trading, contract/futures trading, wallet management, recharge/withdrawal flows, mining products, DApp on-chain monitoring, and an admin panel.

**Key results:**

- **13 Confirmed findings** with complete source-transit-sink-control evidence chains verified in source code.
- **3 Highly Likely findings** with strong evidence but at least one unverified downstream element preventing full confirmation.
- **2 Needs More Evidence findings** with observable control deficiencies but missing sink-side or exploit-path verification.
- **0 Rejected findings** in this review pass.

The most critical confirmed risks are:

1. **OS command injection** in backup and utility classes that execute shell commands from database-stored configuration values with insufficient sanitization.
2. **Missing authorization** on the market-data WebSocket endpoint, allowing unauthenticated clients to subscribe to real-time trading data streams.
3. **Financial control gaps** in wallet transfers (missing recipient eligibility validation, caller-controlled fee amounts) and recharge confirmation (admin can override credited amounts).
4. **Concurrency and atomicity weaknesses** in exchange order execution (in-memory locking only, non-atomic multi-leg pricing with sleep gaps, trigger orders skipping balance deduction).
5. **Infrastructure security deficiencies** including hardcoded encryption keys, unauthenticated Redis, persistent API tokens without expiration, and automatic HTTP redirect following.

Severity distribution across confirmed findings is uniformly **High**, reflecting the financial and operational impact potential of each issue in a cryptocurrency exchange context.

### CONF-01 · Backup Utility Executes Unsanitized Shell Commands from Config-Controlled Values

| Field | Value |
|---|---|
| **Finding ID** | CONF-01 |
| **Related Review IDs** | RC-001-REV-001 |
| **Severity** | High |
| **Confidence** | High |
| **Normalized Issue Type** | OS Command Injection |
| **Bound Function** | BF-009 — Mining and Miner Products (Infrastructure Backup) |
| **Bound Subfunction** | SF-009-01 |

**Entry Point:**
- `BackupUtil.backup()` at `源代码/comm/DB/src/db/util/BackupUtil.java:83-110`
- Type: Scheduled admin/ops process. The backup job reads database-stored properties (e.g., `db.backup.path`, `db.database.name`) via `PropertiesUtilDB.getProperty()` and `sysparaService.find()`, concatenates them into shell command strings, and passes them to `executeLinuxCmd()`.

**Sensitive Point / Risk Locus:**
- `executeLinuxCmd()` at `源代码/comm/DB/src/db/util/BackupUtil.java:51-61` — the method that executes arbitrary OS commands via `Runtime.getRuntime().exec()`.

**Evidence Chain — Source → Transit → Sink → Failed/Missing Control:**

| Role | File Path | Symbol | Line Span | Description |
|---|---|---|---|---|
| **Source** | `源代码/comm/DB/src/db/util/BackupUtil.java` | `backup` | 83–110 | Database-backed properties (`db.backup.path`, `db.database.name`, `backup_stay_days`) are read and used to build shell command strings. Example: `executeLinuxCmd("mkdir " + PropertiesUtilDB.getProperty("db.backup.path"))` at line 100. |
| **Transit** | `源代码/comm/DB/src/db/util/BackupUtil.java` | `backupDB / clearBackup` | 98–116 | Command strings are built by concatenating properties such as `db.database.name`, `db.backup.path`, and retention days. The `backupDB()`, `zip()`, and `clearBackup()` methods produce shell command strings that include config values. |
| **Sink** | `源代码/comm/DB/src/db/util/BackupUtil.java` | `executeLinuxCmd` | 51–61 | If the command contains `>`, `|`, or `\\`, execution is routed to `/bin/sh -c <cmd>`; otherwise `Runtime.exec(cmd)` is called directly. Both paths execute the concatenated string as a shell command. |
| **Failed/Missing Control** | `源代码/comm/DB/src/db/util/BackupUtil.java` | `executeLinuxCmd` | 56–58 | The only filtering checks for `>`, `|`, or `\\` before switching to `/bin/sh -c` execution. No command allowlist, parameterization, or input boundary is applied. Unsafe property values containing shell metacharacters (e.g., `;`, `$()`, `` ` ``) can inject arbitrary commands. |

**Why This Is True:**
The application reads configuration values from the database (an attacker who compromises the DB or a privileged admin can modify these), concatenates them into shell command strings without meaningful sanitization, and executes them via `/bin/sh -c`. The partial metacharacter check is incomplete and does not cover semicolons, backticks, `$()`, or other injection vectors.

**Business Impact:**
If `backup_server_param` or related config properties are attacker-influenced (via database compromise, SQL injection elsewhere, or insider access), arbitrary OS commands execute on the backup host with the application's privilege level. This can lead to full host compromise, data exfiltration, or deployment tampering.

**Remediation:**
1. Replace string-concatenation command construction with `ProcessBuilder` using argument arrays that avoid shell interpretation.
2. Implement a strict allowlist of characters for all config values used in command construction.
3. Move backup configuration from database `syspara` table to a secured, file-system-based configuration with restricted write access.
4. Add integrity checks on backup configuration values before use.

- Type: Internal utility. Any upstream caller can pass a raw string command that is directly executed.

**Sensitive Point / Risk Locus:**
- `ProcessBuilder.start()` at `源代码/comm/DB/src/db/util/CMDUtil.java:17-19`.

**Evidence Chain — Source → Transit → Sink → Failed/Missing Control:**

| Role | File Path | Symbol | Line Span | Description |
|---|---|---|---|---|
| **Source** | `源代码/comm/DB/src/db/util/CMDUtil.java` | `runCMD(String)` | 15–24 | Method accepts a caller-supplied `String cmd` parameter with no validation. |
| **Sink** | `源代码/comm/DB/src/db/util/CMDUtil.java` | `ProcessBuilder.start()` | 17–19 | The raw string is passed directly to `new ProcessBuilder(cmd)` and `processBuilder.start()`, executing it as an OS command. |
| **Failed/Missing Control** | `源代码/comm/DB/src/db/util/CMDUtil.java` | `runCMD(String)` | 15–24 | No validation, allowlist, argument separation, or neutralization exists. The utility is designed to execute arbitrary commands by construction. |

**Why This Is True:**
`CMDUtil.runCMD` is a pass-through to `ProcessBuilder` with zero input validation. Any caller passing attacker-controlled values yields direct command injection. **Remediation:**

2. Audit all callers and ensure no user-controlled input reaches this utility.
3. If the utility must remain, implement a strict command allowlist and reject any invocation that does not match expected patterns.

2. Store token creation timestamp in the database and validate on each request.
3. Implement token rotation on sensitive operations (withdrawal, transfer, password change).
4. Add maximum session duration enforcement at the filter level.

### Appendix E: Audit Limitations

1. **Coverage gap:** Only 18 of 69 identified candidates were reviewed. 51 candidates remain untriaged.
2. **Cross-model divergence:** Two independent auditors produced entirely disjoint finding sets (0 agreement). Auditor 2's 70 findings were not incorporated into this report due to evidence completeness concerns.
3. **Dynamic testing not performed:** All findings are based on static code review. Concurrency issues (HL-03) and runtime behavior were not load-tested.
4. **Frontend excluded:** Compiled Vue.js frontend was not part of this source-code audit.
5. **Database schema not fully parsed:** Entity-to-table mappings are inferred from Hibernate annotations; only sampled tables were verified.
